# Entregável — Semana 01

Use este arquivo como checklist final antes de considerar a Semana 01 concluída. Ele reúne o que é **obrigatório** entregar — os desafios extras em `desafios.md` são opcionais.

## O que precisa existir no repositório

### 1. Pasta `/docs`

- [ ] `docs/requisitos.md` — problema, público-alvo, requisitos funcionais e não funcionais
- [ ] `docs/historias-de-usuario.md` — pelo menos 2-3 histórias no formato `Como [usuário], quero [ação], para [benefício]`
- [ ] `docs/design-system.md` — cores, tipografia, espaçamento e componentes principais
- [ ] `docs/arquitetura.md` — pelo menos uma primeira visão das partes do sistema e suas responsabilidades (esperado com mais profundidade dos veteranos ⚡, mas todo mundo deve ter uma versão inicial)

### 2. Protótipo no Figma

- [ ] Frames criados representando o fluxo principal do projeto
- [ ] Telas conectadas e navegáveis no modo Prototype
- [ ] Link do Figma compartilhável (permissão de visualização, no mínimo) salvo no `README.md` do repositório

### 3. Organização do repositório

- [ ] `README.md` principal, com pelo menos: nome do projeto, breve descrição, link para o protótipo do Figma, link ou referência para a pasta `/docs`
- [ ] Histórico de commits com mensagens claras (não é necessário ser perfeito, mas evite mensagens genéricas tipo "mudanças" em tudo)
- [ ] ⚡ Veteranos: pelo menos uma Issue criada e, idealmente, um Pull Request praticado

## Como revisar antes de entregar

Antes de considerar a semana concluída, faça este teste rápido: peça para outra pessoa (um colega de equipe, alguém de outro grupo, ou até você mesmo revisando depois de um tempo) ler apenas a sua pasta `/docs` e navegar pelo protótipo do Figma, sem nenhuma explicação a mais. Essa pessoa consegue entender:

- [ ] Qual problema o projeto resolve?
- [ ] Quem é o usuário?
- [ ] O que o sistema faz, na prática?
- [ ] Como seria usar o sistema, olhando o protótipo?

Se a resposta for "sim" para as quatro perguntas, sua entrega está no caminho certo. Se não, volte ao módulo correspondente e ajuste.

## O que NÃO é esperado nesta semana

Para deixar claro e evitar ansiedade desnecessária:

- Não é esperado nenhum código funcional ainda.
- Não é esperado que o protótipo do Figma esteja com acabamento visual perfeito.
- Não é esperado que `docs/arquitetura.md` esteja completo e definitivo, principalmente para quem está começando.
- Não é esperado que todos os requisitos estejam 100% amarrados — é normal que eles evoluam nas próximas semanas.

## Onde tirar dúvidas

Lembre-se: os encontros semanais do Coffee & Code existem justamente para isso. Se travar em qualquer ponto, chegue no encontro (ou no Discord) com uma pergunta específica: "travei em X, já tentei Y" costuma ser resolvido muito mais rápido do que "não entendi nada do módulo Z".

Se quiser se aprofundar além do que foi pedido, veja `desafios.md`.

Boa semana de trabalho! ☕
